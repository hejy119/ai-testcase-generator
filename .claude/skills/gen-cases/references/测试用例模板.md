# 测试用例模板

本文件定义用例的**形态**：表格结构、列的定义、文档骨架。
写完不写得好（措辞、质量、覆盖策略）见 `用例编写规范.md`。

## 表格格式

生成用例时**严格使用下方 11 列**，列名与列顺序不得增删改动。

| 编号 | 用例标题 | 模块 | 优先级 | 用例类型 | 前置条件 | 测试数据 | 测试步骤 | 预期结果 | 实际结果 | 可追溯需求条目 |
|---|---|---|---|---|---|---|---|---|---|---|
| TC-001 | 已注册用户使用正确账密登录成功 | 登录 | P0 | 功能 | 1. 用户 `zhangsan` 已注册且状态正常<br>2. 已打开登录页 | 账号：`zhangsan`<br>密码：`Abc@12345` | 1. 在"账号"输入框输入 `zhangsan`<br>2. 在"密码"输入框输入 `Abc@12345`<br>3. 点击【登录】按钮 | 1. 页面跳转到 `/home`<br>2. 页面右上角显示用户名 `zhangsan`<br>3. 数据库 `user_login_log` 表新增一条记录，`login_result` 字段为 `success` | | REQ-1.1 |
| TC-002 | 密码错误时提示且不泄露账号是否存在 | 登录 | P0 | 异常 | 1. 用户 `zhangsan` 已注册<br>2. 已打开登录页 | 账号：`zhangsan`<br>密码：`Wrong@999` | 1. 在"账号"输入框输入 `zhangsan`<br>2. 在"密码"输入框输入 `Wrong@999`<br>3. 点击【登录】按钮 | 1. 停留在登录页，未跳转<br>2. 登录框下方红字提示 `账号或密码错误`<br>3. 密码输入框清空，账号输入框保留 `zhangsan` | | REQ-1.2 |

> 上表两行是**填写示例**，仅用于说明每列该放什么内容。实际生成时全部替换为本次需求的真实数据。

## 各列填写要求

| 列 | 放什么 |
|---|---|
| 编号 | `TC-` + 三位序号（如 `TC-001`）。本次文档内唯一、连续 |
| 用例标题 | 一句话概括本条测什么，能独立看懂 |
| 模块 | 功能所属模块名，同一模块的用例编号保持连续 |
| 优先级 | `P0` / `P1` / `P2` / `P3` 四选一，不写其他形式 |
| 用例类型 | `功能` / `异常` / `边界` / `权限` / `兼容` / `性能` 中选一个 |
| 前置条件 | 执行本条用例前系统必须处于的状态，编号分步 |
| 测试数据 | 本条用例用到的具体输入值 |
| 测试步骤 | 编号分步，每步一个动作 |
| 预期结果 | 执行后的可观测结果，编号分步 |
| 实际结果 | **生成时留空**，由执行人回填。禁止预填任何内容 |
| 可追溯需求条目 | 本条验证的需求文档条目号（如 `REQ-1.2`、`§3.2`）。找不到对应条目的用例不要生成 |

## 文档骨架

生成的文档按以下顺序组织：

1. **元信息** —— 需求名称、需求文档路径、生成日期、用例总数
2. **用例表格** —— 上述 11 列表格
3. **待确认问题** —— 需求中含糊、缺失、自相矛盾的信息（格式见 `用例编写规范.md`）
4. **可复用历史用例** —— 知识库中与本需求相关、本次未重复生成的旧用例编号（无则省略本节）

## 格式转义约定

Markdown 表格单元格内不支持真实换行，且管道符会截断单元格，因此：

- 单元格内换行一律用 `<br>`
- 单元格内容中若出现 `|`，必须转义为 `\|`

这两条如果后续要用脚本把 Markdown 转成 Excel，是必需的；不转则无害，但请统一遵守。
