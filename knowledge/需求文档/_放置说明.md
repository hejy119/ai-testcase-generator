# 需求文档放这里

```
需求文档/
├── 当前/     ← 尚未被取代、其测试用例仍在执行或维护中的需求
├── 归档/     ← 已被新版本取代的历史需求
└── _需求索引.md   ← 所有需求的清单，AI 靠它定位相关文档
```

## 关键：归档的触发条件是「被取代」，不是「生成完用例」

生成的用例里，「需求来源」那一列记录的是文档路径。需求一转走路径就断了，用例的可追溯性会失效；而且需求评审后常要改、要重跑、要补用例，那时文档还在 `当前/` 才用得上。

| 时机 | 动作 |
|---|---|
| 需求新进来 | → `当前/` |
| 生成并执行用例期间 | 留在 `当前/`，需求有小改就直接改这份 |
| 同一功能出了新版本需求 | 老版本 → `归档/`，新版本 → `当前/`，索引里标注「已被 XX 取代」 |

## 两个文件夹的区别

- **`当前/`** —— 用例的「需求来源」**只能**指向这里
- **`归档/`** —— 只用于理解系统全貌、判断本次改动会波及哪些老功能。**不能作为用例依据**，因为它描述的是已失效的旧行为
